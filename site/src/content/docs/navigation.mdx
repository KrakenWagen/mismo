Shared screens navigate with `@mismo/core`, one API that runs on every router: Expo Router, Next.js, TanStack Start and React Router.

```tsx
import { BackLink, Link, Redirect, Slot, useNav, useParams, usePathname, useSearchParams } from "@mismo/core";
```

Code that only runs on one platform, such as a `.native.tsx` file or an app's own routes, can also use its router's API directly.

## Where to go: `To`

Everything that navigates takes a `To`: a route's pattern on its own, or the pattern with its params. Params are required exactly when the pattern has them:

```tsx
<Link to="/settings">Settings</Link>
<Link to={{ href: "/orgs/[id]", params: { id: org.id } }}>{org.name}</Link>
```

Patterns match how you [defined the route](/docs/routes-folder#other-ways-to-define-routes): `/orgs/[id]` in an Expo Router folder, as here, or `/orgs/:id` in a React Router config. Groups aren't part of a pattern: `(app)/home.tsx` is `/home`. See [typed routes](#typed-routes).

## Link

A link to a route. Its children can be anything: text, a row, an image. On native it's a pressable, so it can hold views.

```tsx
<Link to="/sign-up" replace label="Create an account">
  <Row icon="user-plus">Sign up</Row>
</Link>
```

| Prop | |
| --- | --- |
| `to` | Where it goes. |
| `replace` | Replaces the current screen instead of adding one, for a sibling such as sign-in from sign-up. Back still leaves to what came before. |
| `label` | The accessible name, when the content doesn't say where it goes. |

## BackLink

Goes back, or to `fallback` when there's nothing to go back to, such as a page opened from a shared URL:

```tsx
<BackLink fallback="/home" label="Back">
  <ChevronLeft />
</BackLink>
```

## Redirect

Replaces the current screen as soon as it renders:

```tsx
if (!session) return <Redirect to="/sign-in" />;
```

## useNav

Navigates from code:

```tsx
const nav = useNav();

async function onSubmit() {
  await save();
  nav.go({ href: "/orgs/[id]", params: { id } });
}
```

| | |
| --- | --- |
| `go(to)` | Adds a screen. |
| `replace(to)` | Replaces the current screen. |
| `back()` | Goes back one screen. |
| `canGoBack()` | Whether there's a screen to go back to. |
| `preload(to)` | Loads a page's code ahead, so navigating to it later shows it at once. Does nothing on native, where every page is already loaded. |

## useParams

The current route's params, typed by its pattern:

```tsx
const { id } = useParams("/orgs/[id]");
```

## usePathname and useSearchParams

`usePathname()` is the current path, such as `/orgs/acme`. `useSearchParams()` is the query as an object of strings, such as a `token` from a link in an email:

```tsx
const { token } = useSearchParams();
```

## Slot

Where a layout renders its child route. See [layouts](/docs/routes-folder#layouts).

## pathOf

The path a `To` gives, for when you need the string, such as to share a URL:

```ts
pathOf({ href: "/orgs/[id]", params: { id: "acme" } }); // "/orgs/acme"
```

## Typed routes

mismo writes a types file listing every route's pattern and its params. `Link`, `useNav`, `Redirect` and `useParams` are typed from it, so a link to a route that doesn't exist, or without its params, fails the typecheck.

```ts title="src/routes.gen.ts"
// Generated by mismo from the shared routes folder. Do not edit.
import type {} from "@mismo/core";

declare module "@mismo/core" {
  interface Routes {
    "/": Record<never, never>;
    "/orgs/[id]": { id: string };
    "/sign-in": Record<never, never>;
  }
}
```

Keep it somewhere TypeScript can see it, such as `src`, and there's nothing to import.

### Setting them up

Each app already gets its own types file, from the `types` path in its build setup. It has the shared routes plus its platform's own, for the app's own screens.

The shared package's screens need one too. List it in the config, and write it with `mismo types`:

```ts title="packages/app/routes.config.ts"
export default defineRoutes({
  source: "./routes",
  input: expo.input(),
  validFor: [next, expo],
  types: { shared: "./src/routes.gen.ts" },
});
```

```json title="packages/app/package.json"
{
  "scripts": {
    "typecheck": "mismo types --config routes.config.ts && tsc"
  }
}
```

That's all most projects need.

### Routes on one platform

A route with only a `.web` or `.native` file exists on one platform. The shared types leave it out: a shared screen runs on both platforms, so it can't link there.

```tsx title="routes/orgs/[id].tsx"
<Link to="/">All organizations</Link>

{/* @ts-expect-error: /billing is web only, and this screen is shared. */}
<Link to="/billing">Billing</Link>
```

The same link in the web app's own code typechecks, since the web app's types include its platform's routes.

### If you use platform files

If the shared package has `.web` or `.native` files that link to platform-only routes, those files need their platform's types, and the plain files must not see them. That takes a types file and a tsconfig per platform: see [types for platform files](/docs/platform-types).
