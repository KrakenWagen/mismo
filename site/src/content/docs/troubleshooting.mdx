The errors you're most likely to see, what they mean, and the fix. Paths and names in them are your own.

## The routes do not fit every router they are for

```text
The routes do not fit every router they are for:
  (b)/about: /about is also (a)/about, and Next.js allows one page per URL.
```

A route breaks a rule of one of the routers in `validFor`. Every app's build checks every listed router, so this shows up in the native build too. Each line names the route and the router; [Rules](/docs/rules) lists what each router can't take. Rename or move the route, or drop a router you don't use from `validFor`.

## … is hand-written, and the shared routes folder has the same route

```text
app/orgs/[id]/page.tsx is hand-written, and the shared routes folder has the same route. Remove one.
```

An app has its own file where mismo would write a shared route. mismo never overwrites a file without its `// Generated by mismo` line, so it stops instead. Delete the app's own file if the shared route replaces it, as when [moving a screen over](/docs/getting-started#in-an-existing-app), or rename the shared route.

## The root layout belongs to each app

```text
packages/app/routes/_layout: the root layout belongs to each app. Export what it shares as a component.
```

The shared folder has a root `_layout.tsx`. Each app owns its root (the HTML document on the web, the providers and navigator on native), so move it into each app and share what they have in common as a component. A `_layout.tsx` inside a folder or group is fine.

## Catch-all routes, `+` routes

```text
packages/app/routes/[...rest].tsx: catch-all routes are not supported yet.
packages/app/routes/+not-found.tsx: +not-found routes are not supported yet.
```

An Expo Router folder can't hold these yet. Keep them in each app's own routes folder, next to the shared ones. See [defining routes](/docs/routes-folder#not-supported-yet).

## Route options in the wrong place, or unreadable

```text
(app)/orgs/[id]: `reactRouter.loader` runs on the server. Move it to the route's server file, (app)/orgs/[id].server.ts, so the native app never bundles it.
(app)/orgs/[id].server: `next.revalidate` must be a literal, such as `revalidate: 60`. Next.js reads it without running the file.
(app)/orgs/[id]: `next.generateMetadata` isn't a plain value, so the server can't take it from the route's module. Move it to the route's server file, (app)/orgs/[id].server.ts.
routes/orgs/[id].server.ts: `next` should be an object written out, `export const next = { … }`, so its options can be read.
```

A route's options are read from its source, without running it, and each router takes them from a set place: see [route options](/docs/route-options). Move the option the message names, write the object out with each option listed, and keep Next.js's segment config to literals (`60`, `"force-static"`).

## Link has no router

```text
mismo: Link has no router. Point "@mismo/core" at a runtime in the app's build: …
```

A screen used `@mismo/core` in a build without mismo set up: a test, or an app missing the setup step. Add the Vite plugin, `withMismo` for Next.js, or `withMismo` for Metro, as in [Getting started](/docs/getting-started). In tests, mock `@mismo/core` or render through an app's build.

## … should export defineRoutes(…) as its default

```text
packages/app/routes.config.ts should export defineRoutes({ source, input, … }) as its default.
```

The `config` path doesn't point at the routes config, or the file's default export isn't `defineRoutes(…)`. Paths are relative to the app (or to `cwd` for Metro).

If Node can't load the file at all, check its version: the config is loaded with Node's own TypeScript support, which needs Node 22.18 or later.

## … should export one mismo adapter with an output

```text
@mismo/core should export one mismo adapter with an output; it has 0.
```

The CLI's `--adapter` names a package that isn't a router adapter. Pass the adapter of the app's router: `@mismo/next`, `@mismo/tanstack`, `@mismo/react-router` or `@mismo/expo`.

## A typecheck can't find the routes

`tsc` fails on missing route files or a missing `routes.gen.ts` in a fresh checkout. Generated files aren't committed, so a typecheck has to write them first: run `mismo generate` before `tsc`, as in each app's script in [Getting started](/docs/getting-started). On TanStack Start, also run `tsr generate`; on React Router, `react-router typegen`.
