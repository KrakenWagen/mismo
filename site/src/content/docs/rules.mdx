The routers don't all support the same things. Expo Router allows two pages at one URL, in different groups; the web routers don't. A route that's fine for one router can be impossible for another.

## Every build checks every router

Each app builds with one router. If each router's limits were only checked by its own app, a problem would surface late, in an app nobody was working on. A native developer adds `(a)/about` next to `(b)/about`, Expo Router accepts it, and the web build breaks later.

So the config lists every router the routes must stay valid for, and **every app's build checks all of their rules**:

```ts title="packages/app/routes.config.ts"
export default defineRoutes({
  source: "./routes",
  input: expo.input(),
  validFor: [tanstack, expo],
});
```

Now the native build fails too, with the route, the URL, and the router that can't take it:

```text
The routes do not fit every router they are for:
  (b)/about: /about is also (a)/about, and TanStack Start allows one page per URL.
```

Problems from every router are collected and reported together, before anything is written. A failed build leaves the last good routes in place.

An app's own router is always checked, whether it's listed or not. A router that isn't listed adds no limits: a project that only targets Expo Router can use everything Expo Router allows.

## What each router can take

| | Expo Router | Next.js | TanStack Start | React Router |
| --- | --- | --- | --- | --- |
| Pages, params, layouts, index, groups | ✓ | ✓ | ✓ | ✓ |
| Two pages at one URL, in different groups | ✓ | – | – | – |
| `.` or `$` in a file or folder name | ✓ | ✓ | – | ✓ |
| A name starting with `_` or `@`, or a group starting with `(.` | ✓ | – | ✓ | ✓ |

Where a router would quietly treat a name as something else, such as `.` as a path separator on TanStack Start or `_` as a private folder on Next.js, mismo stops the build instead of letting the route change meaning.

## Limits

Beyond the routers' rules, mismo has limits of its own. This is what it doesn't do yet, so you can tell early whether it fits, and what to do instead. mismo is in beta (`0.1.0-beta.1`), and its APIs can still change before 1.0: pin the version you install.

### Defining routes

- **Catch-all and `+` routes** can't be in a shared Expo Router folder: `[...rest].tsx`, `+not-found.tsx`, `+api.ts`. The build stops with an error naming the file. Keep them in each app's own routes, next to the shared ones. See [defining routes](/docs/routes-folder#not-supported-yet).
- **Splats (`*`) and optional segments (`:lang?`)** can't be in a shared React Router config yet. See [React Router](/docs/react-router#define-shared-routes-with-a-config).
- **Two ways to write routes:** an Expo Router folder, or a React Router config. A project picks one, and it doesn't limit which routers run the routes. A Next.js or TanStack folder can't be the format. You can [write your own](/docs/adapters#routeinput).

### Each app's own routes

- **No shared root layout.** Each app owns its root (the HTML document on the web, the providers and navigator on native). Share what they have in common as a component. See [the root layout](/docs/routes-folder#the-root-layout).
- **Router-only features stay in the app.** Not-found pages, API routes, and parallel or intercepting routes use each router's own conventions, so they live in that app's own routes, not the shared folder.

### Screens

- **A shared screen uses `@mismo/core` for navigation.** It runs on every platform, so it can't call one router's `Link` or data hooks. Code that runs on one platform, such as a `.web.tsx` file, can use its router's API directly.
- **Shared screens are client components on Next.js.** They also run on the phone, so they can't be server components. Next.js still renders them on the server for the first load, and the generated server page carries each route's metadata and caching. See [Next.js](/docs/nextjs#server-and-client).
- **A loader's data isn't available to a shared screen.** Read it in the router's own options (React Router's `meta` gets `loaderData`), or in a web-only version of the screen. See [route options](/docs/route-options#reading-the-data-in-a-screen).

### Server code

- **TanStack Start runs a loader in the browser too,** so a route's server file is in the web app's browser bundle. Keep server-only work in a `createServerFn`. See [TanStack Start](/docs/tanstack-start#route-options).
- **Expo Router takes no server options.** Its server loaders and API routes aren't part of the native app mismo builds. A route's server file never reaches native.

### Routers and versions

- **Native is Expo Router only.** React Navigation isn't supported.
- **Version ranges:** Expo Router `>=58 <59`, Next.js `>=16 <17`, React Router `>=8 <9`, TanStack Router `>=1.160`, React 19. See [routers](/docs/routers).
